5. PROTECT EXISTING BOOKINGS AND PAYMENTS

Document versioned publication rather than destructive edits to sold terms.
A published change creates a new package version or equivalent immutable
revision. Preserve the stable package identity and historical versions.

Each confirmed booking retains the purchased snapshot:
- Package/version reference and purchased display details.
- Duration, session start/end, and reserved cleaning buffer.
- Guest allowance and included/selected services.
- Price line items, fees, discounts if applicable, and final total.
- Accepted policy/consent versions and quote reference.

Changing a catalog package must NOT silently change existing bookings,
receipts, historical reports, purchased inclusions, or active access PINs.
Deactivation prevents new sales under the defined rule; it does not
cancel existing reservations. Preserve versions referenced by bookings.

Differentiate:
- When a package version becomes available for new purchases.
- Which future cinema session dates that version may serve.

Use explicit timezone-aware boundaries, with Asia/Colombo for venue-local
rules. Define version precedence and prevent ambiguous overlapping versions
for the same package and scope.

An in-progress checkout is bound to an authoritative versioned quote
with an expiry. Document the recommended policy to honor valid quotes
and require clear acceptance of refreshed terms after expiry.

Reconcile existing “revalidate price at payment confirmation” wording:
validate against the accepted quote, payment amount/currency, and current
reservation eligibility, not silently against a newly published rate.

A delayed or duplicate webhook must not cause duplicate booking,
retroactive repricing, or an unapproved extra charge. Define reconciliation
and recovery for expired holds, late successful payments, and conflicts.
Distinguish quote expiry from evidence that payment was completed in time.

Changing a purchased booking is a separate authorized amendment workflow:
check availability, obtain necessary customer acceptance, resolve payment
or refund differences, update reserved intervals, then coordinate access
and notifications with retry/failure handling.

No package edit may extend PIN validity, disturb an active session,
or bypass conflict checking and required cleaning time.
